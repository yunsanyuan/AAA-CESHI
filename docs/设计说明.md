# 设计说明

本仓库是花间集的 **HTTP 黑盒测试**，被测系统在 [yunsanyuan/sanyuan](https://github.com/yunsanyuan/sanyuan)。

## 被测系统实际长什么样

| 常见接口测试模板 | 花间集 |
| --- | --- |
| `/api/xxx` + JSON | Django MVT，返回 HTML |
| JWT / Bearer | Session Cookie，另有 CSRF |
| 前台 CRUD 商品 | 商品增删改在 Admin；会员端是查花、加购、下单、改资料 |
| 进程内 `TestClient` | sanyuan 根目录另有 pytest-django；**本仓库发真实 HTTP** |

若写成 `Authorization: Bearer` 或 `POST /api/products`，请求会 404，测的是假接口。

## 本仓库测哪一层

```
pytest + requests  ──HTTP──►  runserver :8000  ──►  Django 视图  ──►  MySQL
         ▲
      本仓库
```

sanyuan 里的 `tests/` 不经过网卡。本仓库像顾客进店点单：登录态、CSRF、302、404 必须在真实端口上成立。

## 入口怎么选

会员端真实路径（不是 REST 资源名）：

1. `POST /accounts/login/` — 登录（302 `/` + `sessionid`）
2. `GET /shop/`、`GET /shop/<id>/` — 查商品
3. `POST /shop/<id>/add/` + `GET /orders/cart/` — 给订单准备数据（增/查的前半）
4. `GET /member/`、`GET /member/profile/` — 会员查询
5. 异常：`/shop/999999/` → 404；未登录 `/member/` → 302；缺 password；假 `sessionid`；加购缺 CSRF → 403

缺 CSRF 和假 Cookie 不是同一类问题：前者是跨站提交防护，后者是未认证。

## 明确不测

- 不把被测系统改成 REST 以便写测试
- 不默认跑 `POST /orders/checkout/`、支付、充值（演示库会留下真实订单/储值）
- 不打 `/admin/` 做商品增删改
- CI 不启 MySQL 和 runserver，只 `--collect-only`

## Fixture

- `base_url`：默认 `http://127.0.0.1:8000`，连不上则退出并提示先启动 sanyuan
- `anon_session` / `member_session`：`requests.Session()` 自动带 Cookie
- `sample_product`：从花市页解析详情链接，不写死商品 id
- `extract_csrf`：兼容 hidden input 两种属性顺序

POST 合同：GET 表单页 → 解析 `csrfmiddlewaretoken` → POST 时带上，并设 `Referer`，`allow_redirects=False`。
